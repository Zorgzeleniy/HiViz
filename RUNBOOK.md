# HiViz — Runbook (development notes)

## Layout
- `core/AUDIT.md`, `core/APPLY.md` — the single source of truth for procedures. Edit ONLY these.
- `templates/` — per-harness wrappers with `{{AUDIT_BODY}}` / `{{APPLY_BODY}}` placeholders.
- `bin/hiviz.js` — installer: detects harnesses by marker dirs, renders templates, idempotent copy. `status | init [--dry] | uninstall`.
- `meters/` — v0.2: fixed `mcp_footprint` (live MCP context-cost meter) lands here.

## Conventions
- English only. All outputs land in `.hiviz/` inside the audited project.
- The five invariants (README "What it never does") are the product — any change to them is a semver-major decision.
- Probes: `claude -p` / `codex exec` / `omp -p` / `pi -p` / `cursor-agent -p` / `opencode run` — `--harness <name>` or auto-detected, never hardcoded.
- drift×mcp (v0.6): check.py auto-loads <base>/.hiviz/mcp_footprint.json when present (or --mcp-footprint); rows mcp:<server>: STALE if tokens>=--mcp-min-tokens (500) AND (calls==0 OR last_used older than --mcp-stale-days 30); meter-error rows → UNVERIFIABLE; missing file → silent skip (no phantom rows). T1 asserts the full merge (6 OK / 3 STALE / 2 UNVERIFIABLE on fixture).
- Output formats (`render/hvfmt.py`, stdlib, shared by every engine and the rig): `--format auto|pretty|md|json`. `json` = ONE ASCII-only document on stdout (diagnostics stay on stderr): drift, constitution, blame, meters, `report.py --summary`; translate has no json yet. The installer (`bin/hiviz.js`) takes the same switches — `pretty` = symbols + color + a status table on a terminal, `md` = the legacy text (pipes, CI, agents), `json` for `status` only (init/uninstall refuse it, exit 2). `md` (legacy markdown tables) is what agents and CI get — auto picks it whenever stdout is not a TTY, so skill procedures and T1 parse nothing new. `pretty` = box tables + status symbols (✔ ✘ ◐ ○ !), color only on a TTY (`NO_COLOR` off, `FORCE_COLOR` on), ASCII fallback when the stream encoding can't carry the symbols. `HIVIZ_FORMAT=pretty|md` overrides auto. Engines import it via `../render`, so it ships with the existing `render/` dir (installer, npm `files`, plugin tree) — no new wiring. JSON outputs (`--out`) are unchanged. Windows: real console → VT is switched on via `SetConsoleMode` and restored at exit (legacy console / redirected → plain); streams use `errors=replace`, so a cp866/cp1251 pipe degrades to `?`/ASCII instead of crashing; Git Bash (mintty) is not a TTY for native Python → use `PYTHONUTF8=1 HIVIZ_FORMAT=pretty FORCE_COLOR=1`; `HIVIZ_ASCII=1` forces ASCII symbols when the console font lacks ✔ ◐ ⠋. Not verifiable in Linux CI: fonts/glyph coverage, conhost vs Windows Terminal rendering. T1 simulates kernel32 (`WIN_SIM`) and Windows paths/BOM/CRLF.
- Report view (`render/report.py`): the funnel report's decision rows are `| id | where | line | why | B | → verb |` (core/AUDIT.md contract: `where` = absolute path:line, `B` = bytes the verb touches, `why` = `<category>: <reason>`). HTML = sticky progress + sort by effect + batch by category + per-row yes/no/keep/as-condition + conflict sides + `decisions.md` export (nothing pre-filled; state lives in the browser's localStorage). `--summary` prints the same for a terminal; T2 prints it after the audit. Reports without `where`/`B` (≤0.7.1) still render. T1 drives the page in headless Chrome when present.
- Probe control (`constitution/control.py`, used by `constitution/run.py`): after a PASS/FLAKY, copy `--corpus` (instruction-like files ≤512 KB, never `.git`/`.hiviz`/`*.bak-*`/symlinks; caps 3000 files / 24 MB → "unavailable"), drop every line containing the guarded phrase (+ indented continuation), `git init` the copy when the project is a repo, run `--control-runs` samples (default 3) in parallel with `$PWD` = the copy, plus a canary (a token appended to the copied file; the harness must report it, else the copy proves nothing). Outcomes: `absent` (PASS stays, proof `line`; `project` when no line was named), `present` (→ UNPROVEN), `unavailable` (PASS stays, `control skipped: <reason>`). `tests/fake_agent.py` models the harness traits that matter (cwd from `$PWD`, a system prompt no file can remove, a global config, a config-dir-only harness); T2 (full, opencode): 13/13 in 27m24s with the control really run — both library rules `PASS`/`line` before and after the apply; the check fails if a control is skipped (it once passed with it skipped). `tests/rig/probes.py` = 7 T1 scenarios, each rule checked by breaking it (12 mutations, plus a structured-file case). Structured files (json/toml/yaml) that merely mention the phrase are copied untouched and named in the control's detail — an early version refused the control because of them (found when the T2 sandbox kept the library `.toml` inside the corpus).
  Real-harness facts behind the defaults (OpenCode 1.18 + big-pickle, 189 runs, one git project per run, session directory verified in the DB): AGENTS.md is loaded with and without git; probes with the rule present passed 53/54; specific markers fail without the line (conv 1/6, testloc, envlocal, gateway, redact, commit-gate 0/6) while `git stash` (refusal echo) and library `destructive-gate` (another line / the system prompt) pass 6/6; a single control sample flips 1 time in 3 on a specific marker → 3 parallel samples; asks without the no-tools note went to grep/glob in 10/54 control runs, with it 0/108. Median 35 s per call → the 9-test suite took 9m18s with the control (≈1.8× without it). **An earlier probe experiment of mine was wrong**: OpenCode takes its cwd from `$PWD`, `subprocess(cwd=…)` alone left every run in the parent directory — always verify a harness test against the session's recorded directory.
- Apply verifier (`apply/verify.py`, deterministic, stdlib): decisions.md (rows + DECISION column, parsed by `render/report.py`) + each file's newest `<file>.bak-*` (not older than the decisions: an older one belongs to an earlier apply) → per row OK / REVIEW / UNVERIFIABLE / FAIL(+`restore`|`apply`), plus file-level FAILs (a line changed or added that no row covers, edit without backup, a backup for a file no decision names) and a ledger check. Blank lines are ignored. Limits, on purpose: a rewrite's or condition's CONTENT is never judged (listed for a human); edits that touch neighbouring lines merge into one diff hunk, so a deletion's replacement text next to a rewrite is shown as REVIEW, not FAIL; a quote that cannot be found makes its row UNVERIFIABLE and an edit under it FAIL. `tests/rig/apply.py` holds 7 T1 scenarios (each rule was checked by breaking it: 7 mutations, all caught); `--t2x` runs the verifier on the real model's apply and requires it to agree with an independent oracle. The T2 sandbox now carries `engines/` copied from the checkout (found as `<skill dir>/../../engines`), so skills never run a stale `~/.hiviz/engines`.
- T2x (`python tests/run.py --t2x`, ~3-10 min, real model): builds a report over the sandbox files, clicks decisions in the HTML page (headless Chrome: batch, no, keep, as-condition, one row left empty), takes the exported `decisions.md`, runs `hv-apply` on it WITHOUT restating the DECISION semantics in the prompt, then asserts exactly the approved lines changed. Run it after touching `render/report.py`, the row grammar or `core/APPLY.md`.
- T2 harness: `HIVIZ_T2_HARNESS=omp` (default, needs the stored login / `ZAI_API_KEY`), `opencode` (`HIVIZ_T2_MODEL`, default `opencode/big-pickle` — a free model, no key), or `claude` / `codex` / `pi` — all three ride the maintainer's ZAI key (bigmodel.cn anthropic/openai facades, `CLAUDE_T2_KEY` or `ZAI_API_KEY`; auto-exported from the omp login when absent). Codex T2 runs the 0.50.0 line installed as the npm alias `codex-t2` (`npm i -g codex-t2@npm:@openai/codex@0.50.0`, alongside the current CLI T1 discovery tests): ≥0.106 dropped `wire_api = "chat"` and bigmodel has no `/responses`. Its sandbox runs `danger-full-access` so apply can spawn nested probes. Bigmodel throttles bursts at the connection level (reset after ~5 min of polling) — T2 runs are spaced, not retried hot. Each model phase shows a live spinner with elapsed/budget and a progress hint (report.md lines, .bak count).
- CI jobs (`.github/workflows/t1.yml`): `lint` (ruff F+B, `ruff.toml`), `min-python` (3.10 must fail with the clear "needs Python >= 3.11" message), `t1` matrix = ubuntu × py3.11/3.13 + Node 16 + macOS + Windows. macOS/Windows are `continue-on-error` until one run is green (never run in CI before — flip it then). `.gitattributes` pins `eol=lf`: Windows runners check out with autocrlf and `build-plugin --check` compares bytes. Node 16: `fs.rmSync` swallows EACCES there — `bin/hiviz.js` uses `rmChecked`.
- CI (.github/workflows/t1.yml, original notes): syntax + parity (tests/parity.py — heredoc в yaml с отступами валит bash→python IndentationError, поэтому отдельный файл) + T1. ## Test rig (tests/run.py → tests/rig/)
- Layout: `tests/run.py` = entry point (`--t1 | --t2 | --t2x | --all`); the checks live in `tests/rig/` — `core` (state, `check`, `sh`, fake-HOME + browser helpers), `installer`, `engines`, `apply` (the verifier), `output` (formats, JSON, report page), `discovery`, `harness`, `t2`. `tests/` is NOT in the npm tarball: users never run it — it is the maintainers' regression rig.
- Harness discovery (T1, no model, no credentials): `tests/rig/harness.py` asks the REAL CLI which hiviz skills it sees after `hiviz init` — Claude Code (stream-json `init` event), Codex (`app-server` `skills/list`), pi (`--mode rpc` `get_commands`), omp (`--mode rpc` `get_available_commands`; it refuses to start without a default model, so it gets a placeholder key that is never sent anywhere), OpenCode (`debug skill`) — and whether the sandbox that `profile_setup` really builds (T2 layout) is discovered. A missing CLI is skipped; `HIVIZ_REQUIRE_HARNESSES=claude,codex,pi,opencode,omp` makes it a failure (CI job `harness-discovery` installs pinned versions; omp needs bun >= 1.3.14). NOT covered: Cursor (`cursor-agent` validates the API key online before it lists anything) and Windsurf (no agent CLI) — file placement only. Quirks found on the way: `opencode debug skill` truncates at 64 KiB when stdout is a pipe (the rig writes to a file); omp reads `PI_CODING_AGENT_DIR` as its agent dir, so the rig removes it from the environment and the installer, which writes omp adapters to a fixed `~/.omp/agent`, misses an omp that was started with that variable set.
- Adding a harness to T2 (model runs): give its entry in `harness.py` an `argv(prompt, sandbox, model)` (+ `run_env(sandbox, model)` when the CLI needs env vars, `skills_dir` / `extras`), then `HIVIZ_T2_HARNESS=<name> python tests/run.py --t2x`. Wired: omp (stored login), opencode (free model), claude / codex / pi (ZAI key). RULES.md reaches the model on omp/opencode only; pi/codex/claude read AGENTS.md — the T2 fixture plants both.
- Active checks: drift `shell` / `port_open` facts run what facts.toml names; `--active-checks auto|on|off` (`HIVIZ_ACTIVE_CHECKS`, Action input `active-checks`). auto = off for `pull_request_target` and fork PRs (and when the event payload is unreadable), on elsewhere; skipped facts are UNVERIFIABLE. T1 strips the CI's own `GITHUB_EVENT_*` so the engines under test stay hermetic.
- T1 deterministic (free): render, installer/uninstall idempotency (per-harness + env overrides + symlinks + plugin coexistence), engine deploy/mirror, meters (stdio/HTTP discovery + usage), drift statuses, constitution engine via fake harness (all verdict classes + no-shell/ERROR), blame (marker/--line + per-harness log mining), translate, output formats + JSON + report page (incl. a headless-browser export round-trip), harness discovery on the real CLIs, plugin tree + npm tarball. Current: 95/95 with Claude Code, Codex, pi, OpenCode and omp installed (each missing CLI turns its two checks into one "skipped"); POSIX-only chmod eacres check skipped on Windows.
- T2 E2E (LLM, glm-5.3-flash:high in sandbox profile with 21 vendored popular skills + realistic AGENTS.md): audit → recall → deterministic decisions → apply → post-asserts. Current best: 13/13 effective (12 PASS + recall-8/8 with paraphrase-robust markers), ~20 min.
- Rig-caught product bugs so far: relative paths in decisions edited the fixture source (→ absolute paths + integrity check); "ask user for probes" conflicts with headless (→ pre-authorization clause in core/APPLY.md); report held in chat (→ incremental writes); hot agent.db copy hangs omp (→ sqlite3 backup API + preflight).
- Blame (v0.4): `blame/blame.py` — ledger (`.hiviz/ledger.jsonl`, written by apply) + session-log mining (omp sessions jsonl: message.content[].type=="toolCall", model from model_change events, TOUCHED-flag when marker in payload) + verified-from-constitution; `/hv-blame` adapters. Live-proven: mined the real Sep-15 edits of factcheck-response from our own session log. Gotcha: file-name prefilter must be case-insensitive (agents.md vs AGENTS.md). INSTALLER EDIT RULE: after every edit to bin/hiviz.js run the T-key parity check (defined vs used) — three times a line got eaten by anchored inserts.
