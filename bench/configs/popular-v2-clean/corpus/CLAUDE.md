# ChatGPTBox - Browser Extension

Cross-platform browser extension integrating ChatGPT and other AI models into web browsing: chat dialogs, selection tools, site-specific adapters.

## Commands

- `npm ci` — install (audit warnings on dev-only deps are acceptable)
- `npm run dev` — webpack watch; stop gracefully (never mid-compilation) when switching branches or after dependency/config changes
- `npm run build` — production; ~35 s measured, allow 5–10 min
- `npm run pretty` — Prettier; **run before linting**
- `npm run lint` — ESLint; **run before committing — CI fails otherwise**
- `npm run analyze` — bundle size; `npm run build:safari` — macOS/Xcode only
- Node 20+ required

## Hard rules

- **No automated tests exist** — every change is validated by manually loading the built extension in a browser.
- Extension files **cannot be served over HTTP for testing** — load them as a proper extension (`build/chromium/` unpacked in Chrome; `manifest.json` as temporary add-on in Firefox).
- After a rebuild: reload the extension and refresh the page so content scripts re-inject.
- Do not commit secrets, API keys, or user data. Keep manifest permissions minimal and justified. All network/API logic lives under `src/services/apis/` with auditable endpoints.
- Do not interrupt builds or long-running commands unless they appear hung.

## Stack & structure

Preact + SCSS + Webpack 5. Manifests: `src/manifest.json` (MV3, Chromium) and `src/manifest.v2.json` (Firefox — background page, not service worker).

```
src/
├── background/             # background script / service worker
├── components/             # reusable UI components
├── config/                 # configuration management
├── content-script/         # main content script
│   ├── site-adapters/      # per-site integrations
│   ├── selection-tools/    # text-selection features
│   └── menu-tools/         # context-menu features
├── pages/IndependentPanel/ # standalone chat page
├── popup/                  # toolbar popup
├── services/apis/          # API clients and wrappers
└── utils/                  # helpers
```

Production build emits variants into `build/`: `chromium/`, `firefox/`, and `-without-katex-and-tiktoken` minimal variants; distribution zips per browser. Validate by checking the expected files exist in `build/chromium/` (bundle sizes are not criteria).

## Conventions

- Component directories PascalCase; feature folders kebab-case; entry files `index.jsx` / `index.mjs`.
- Avoid heavy dependencies; justify any addition and keep bundle size under control.
- Commit subject: imperative, capitalized first word, wrap ~72, blank line before body, explain what and why. PRs: link issues, summarize scope, screenshots for UI changes, note `src/_locales/` changes in the description.

## Localization

Source of truth: `src/_locales/en/main.json` — **do not change existing keys**. Add new strings to `en` first, then propagate. Register new locales in `src/_locales/resources.mjs`. Preserve placeholders and product names. Traditional Chinese uses `src/_locales/zh-hant/main.json` — avoid zh-CN terms.

## Common tasks

- New site adapter: file in `src/content-script/site-adapters/`, register in its `index.mjs`, keep selectors minimal with feature detection, verify on Chromium + Firefox.
- New selection tool: `src/content-script/selection-tools/`, keep UI and logic separate, reuse `src/utils/` helpers.
